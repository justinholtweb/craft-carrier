# Plugin Store promo images

Marketing images for the Carrier listing on the Craft Plugin Store, in the theme of the plugin's
marketing page at [justinholt.com/plugins/craft-carrier](https://justinholt.com/plugins/craft-carrier).

## Building

```bash
./build.sh          # all slides
./build.sh "2 6"    # just slides 2 and 6
```

Output lands in `out/` as `carrier-promo-N.jpg`, 1920×1080 (rendered at 2× in headless Chrome, then
downsampled and converted to JPEG in one `sips` pass). Promos ship as JPEG, never PNG.

Chrome occasionally dies with a `Trace/BPT trap` partway through a full run. It is transient and
the script uses `set -e`, so re-run the slides it did not reach rather than assuming a real failure.

## Slides

| # | Slide | Shows |
|---|-------|-------|
| 1 | Cover — name, tagline, app icon, price | — |
| 2 | `16 carriers` → `1 gateway` | the whole pitch, in one line |
| 3 | A free add-on for every carrier | the eight add-on icons, what each covers |
| 4 | It never buys the same label twice | three ways in, one claim key; refused vs. no answer |
| 5 | A locker, picked at checkout | the point picker, its three point modes, the payment guard |
| 6 | Written back to the order | a tracking history, a late scan ignored, delivered status |
| 7 | One print job from the order index | what bulk printing makes of each label mix |
| 8 | Answerable from the command line | `connections/test`, a `--dry-run` label, `tracking/refresh` |
| 9 | Every carrier, and what it can do | **screenshot** — connections and installed carriers |
| 10 | The whole shipment, on the order | **screenshot** — a delivered shipment with tracking |
| 11 | Rates that fail open | **screenshot** — a live-rate method's price settings |
| 12 | When nobody knows, a person decides | **screenshot** — Problems, one uncertain and one refused |

Slides 9–12 are **real control-panel screenshots**, not mockups. They come from the plugin-testing
harness running the built-in Mock Carrier, which is why every connection and shipment says "Mock
Carrier" rather than a carrier's name. Nothing in a screenshot may look like a real carrier's
account. To re-take them:

```sh
tests/integration/run.sh /var/www/craft-carrier/tests/integration/promo-fixtures.php   # prints the ids
# put the printed connection, method and order ids into plugin-shots/specs/carrier.json, then:
cd ~/Sites/plugin-shots
CP_BASE=http://127.0.0.1:$(docker port ddev-plugin-testing-web 80 | cut -d: -f2) node capture.mjs out/carrier specs/carrier.json
cd -
tests/integration/run.sh /var/www/craft-carrier/tests/integration/promo-fixtures.php teardown   # always
```

`promo-fixtures.php` makes two Mock connections and a store-pickup one, four checkout methods, a
delivered order (its label is re-dated a day back so the mock's tracking has moved through every
stage), a locker order in transit, and a refused and a timed-out purchase for Problems. The harness
is shared, so the spec hides other sessions' rows with `:has()` selectors keyed on those ids.

The host router has answered 404 for `plugin-testing.ddev.site`, so the capture goes to the web
container's published port directly. The harness shows a "project config pending" banner, so the
order and method captures are cropped with `sips -c <h> <w> --cropOffset <y> 0`: `carrier-order.png`
from y=190 (below the banner) to the "Ship more" form, and `carrier-method.png` to the Price and
"When it is offered" sections. The raw captures are in `plugin-shots/out/carrier/`.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette and fonts
are the plugin site's: accent `#5C6DF2`, light accent `#8A97F7` and gold `#ffd166` on Erpy's dark
ground, Jersey 20 for display and Inter for body. The tile itself is `#3B4CCA`.

`assets/` holds the fonts and the icons, all written by `icon-gen.py` — don't edit them by hand:

- `icon.svg` — the app icon, a copy of `../src/icon.svg`.
- `watermark.svg` — the parcel glyph **with the tile stripped off**, cropped so its faces run off
  the edge. The faces are large solid areas, so it is drawn at 2% opacity, lower than Erpy's 3%.
  The cover suppresses it.
- `addons/<key>.svg` — the eight add-on icons, for slide 3. Their corner marks are generic (truck,
  plane, pallet, pin…); carriers' logos are never used.

**`.rule` is already taken** by the eyebrow's hairline. Pick specific class names for anything new
(`.maprule`, `.outcome`, `.picker`), or a generic one will restyle something three slides away.

**The terminal bleeds off the right edge on purpose** (`.term { right: -110px }`), so a long line
is cut without warning rather than wrapping. Keep console output under about 48 characters.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.

## The add-on decks

Every add-on's `promos/` is generated from `addons/`:

```sh
python3 addons/generate.py              # all eight
python3 addons/generate.py gls boxnow   # just these
cd ../../craft-carrier-gls/promos && ./build.sh
```

Seven slides each. Slides 2 (what it does), 3 (the connection form) and 5 (services, label formats,
pickup points) come from `addons/carriers.json`, which is dumped from the carriers themselves, so a
slide can never claim a feature the carrier does not declare. Refresh it whenever a carrier's
`capabilities()`, `services()` or `settingsFields()` change:

```sh
docker exec -w /var/www/html ddev-plugin-testing-web \
    php /var/www/craft-carrier/tests/tools/dump-carriers.php > addons/carriers.json
```

The rest of the copy — tagline, connecting prose, three carrier traps, and what to check in the
sandbox — is in `addons/decks.json`, taken from each add-on's README and its carrier class's
**UNVERIFIED** notes.
